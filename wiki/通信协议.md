# 通信协议（V2）

> **完整字节级规范以仓库 [`docs/protocol-v2.md`](https://github.com/wuandx/car_sim/blob/master/docs/protocol-v2.md) 为准**（本页是摘要，两者不一致时以仓库文档为准）。

## 帧格式

```
0xA5 0x5A | Type(1B) | LEN_H LEN_L(2B 大端) | RSV(1B, 填 0x00) | Payload[N] | CRC_L CRC_H(2B 小端)
└──────────────── 6 字节帧头 ────────────────┘                  └── N 字节 ──┘
```

- **LEN** = payload 字节数（不含帧头与 CRC），上限 16 MB
- **CRC16** = CRC-16/CCITT-FALSE（poly `0x1021`、init `0xFFFF`、不反射），覆盖帧头 + payload，**小端存储**
- 自检向量：`crc16("123456789") == 0x29B1` —— 下位机移植后先跑这个自检

> ⚠️ 历史坑：早期文档误写成 Modbus CRC（poly 0x8005）。固件必须用 CCITT-FALSE，否则上位机 CRC 错误计数飙升、全部丢帧。

## 帧类型

| 值 | 类型 | 方向 | payload |
|----|------|------|---------|
| `0x01` | Image | 下→上 | 子头 7B：`width(2B) + height(2B) + stride(2B) + format(1B)`（大端）+ 像素 |
| `0x02` | Command | 上→下 | `cmd_id(1B) + param_count(1B) + (channel, type, value)×N`，值小端 |
| `0x03` | Response | 下→上 | `cmd_id + status + 回写参数`（status: 0=OK, 1=通道越界, 2=值超限…） |
| `0x04` | Telemetry | 下→上 | 子头 3B：`start_channel + channel_count + sample_type` + 交织样本 |
| `0x05` | Heartbeat | 双向 | `ping/pong + device_id + uptime`，超时判链路断开 |

**sample_type**：`0`=int16（2B/样）、`1`=float32（4B/样，IEEE-754 小端）、`2`=int32（4B/样）

**图像 format**：`0`=Grayscale8、`1`=RGB888；`stride > width` 时上位机自动去行 padding（推荐发送方保证 stride == width）

## 示例

**遥测**：从通道 2 起 3 通道 int16、2 个采样点：

```
A5 5A 04 00 0F 00  02 03 00  00 20 00 30 00 40  00 21 00 31 00 41  [CRC_L] [CRC_H]
└── 帧头(6B) ──┘   └ 子头 ┘  └── 采样点 0 (3ch) ┘ └── 采样点 1 ──┘
```

**调参命令**：通道 0 写 float32 = 12.5：

```
Payload: 00 01 00 06 00 00 20 41
         │  │  │  │  └─ 12.5 (IEEE-754 小端)
         │  │  └─ typeCode 0x06 = float32
         │  └─ param_count = 1
         └─ cmd_id = 0
```
