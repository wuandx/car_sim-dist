# 构建指南

> 源码编译。只想用的话直接下载 Release，看[快速开始](快速开始.md)。

## 依赖总览

| 依赖 | Windows | Linux (Arch) |
|------|---------|--------------|
| Qt | 5.15.2 mingw81_64 | `qt5-base`（官方仓库） |
| Qt 附加模块 | 安装器勾选 SerialPort/Bluetooth | `qt5-serialport`、`qt5-connectivity`（AUR） |
| 编译器 | MinGW 8.1.0 **64 位** | gcc/g++ 任意现代版本 |
| 构建系统 | qmake（或 CMake） | qmake（或 CMake） |

## ⚠️ 第一原则：64 位

主程序与算法插件 DLL 必须同为 **x86-64**。32 位主程序加载插件会报 `ERROR_BAD_EXE_FORMAT (0xC1)`。

## Windows 构建

```bat
set PATH=D:\Qt\5.15.2\mingw81_64\bin;D:\Qt\Tools\mingw810_64\bin;%PATH%
cd build_qmake
qmake ..\UpperComputer.pro
mingw32-make
```

产物：`bin\UpperComputer.exe`。

**PATH 陷阱（重要）**：如果系统 PATH 里存在 32 位 MinGW 且排在前面，会混编出 32/64 位 .o，链接报 `undefined reference to QWidget::...`。此时让 qmake 把编译器固化成绝对路径：

```bat
qmake ../UpperComputer.pro "QMAKE_CXX=D:/Qt/Tools/mingw810_64/bin/g++.exe" "QMAKE_LINK=D:/Qt/Tools/mingw810_64/bin/g++.exe"
```

换编译器或清理 .o 后**必须重跑 qmake**，否则 Makefile 里还是旧路径。

## Linux 构建（Arch）

```bash
sudo pacman -S qt5-base
yay -S qt5-serialport qt5-connectivity
sudo usermod -aG uucp $USER        # 串口权限，重新登录生效

cd build_linux
qmake ../UpperComputer.pro
make -j$(nproc)
./run_linux.sh
```

产物：`bin_linux/UpperComputer`。GUI 无头冒烟可加 `-platform offscreen`。

## 平台目录分离（重要约定）

工程按 `win32{}`/`unix{}` 作用域**完全分离**两边的产物目录：

| 平台 | 可执行 | 目标文件/中间产物 |
|------|--------|-------------------|
| Windows | `bin/` | `build/`、`build_qmake/` |
| Linux | `bin_linux/` | `build_linux/` |

**绝不在 Linux 上往 `bin/`、`build/` 输出**（反之亦然）——ELF 与 PE 目标文件混入同一 obj 目录会导致另一平台增量链接"混编"失败。截图/录像/算法等运行时目录在各平台 exe 同级自动创建。

## 验证构建成功（防"假编译"）

1. make 日志非空且 `error:` 计数为 0
2. exe 的修改时间已更新
3. `build*/obj/*.o` 数量合理（约 55 个）
4. 日志含最终链接行
