# 故障排查

按现象索引。都来自真实踩坑记录。

## 连接类

**Q：连接后什么数据都收不到**
1. 底部 `RX` 计数在涨吗？不涨 → 物理链路问题（串口线/波特率/IP 端口）
2. RX 涨但 `CRC` 计数也涨 → 下位机 CRC 算法不对：必须是 **CCITT-FALSE**（poly 0x1021, init 0xFFFF, 不反射, 小端存储），不是 Modbus。自检：`"123456789" → 0x29B1`
3. 协议下拉选对了吗？图传/示波要 `V2 协议`；`RawData` 是裸字节直通示波

**Q：Linux 串口打不开**
- 权限：`sudo usermod -aG uucp $USER`（Arch；Debian 系用 `dialout`），重新登录
- 设备名：Linux 是 `/dev/ttyUSB0`、`/dev/ttyACM0`，不是 COM 口

**Q：Linux 上蓝牙选不了**
- 当前版本置灰（BlueZ 路径待真机实测）。用串口或 WiFi。

## 显示类

**Q：图传有画面，示波是空的**
- 看示波窗口内部 `帧: N`：在涨 → 是显示问题（检查通道/量程）；恒为 0 → 遥测帧没到达（查下位机遥测子头：3 字节 `start_channel + channel_count + sample_type`）
- 主窗口底部 `帧数: N` 只计图像帧，遥测不计——它为 0 是正常的

**Q：示波器上一条恒定值信号看不见**
- 历史版本对恒定信号量程坍缩（压成 1px），已修复。若复现请报 issue。

## 构建类

**Q：Windows 链接报 `undefined reference to QWidget::...` / `WinMain@16`**
- 典型**混编**：32 位 MinGW 混进了 64 位构建。清理全部 .o，重跑带 `QMAKE_CXX`/`QMAKE_LINK` 绝对路径的 qmake（见[构建指南](构建指南.md)）

**Q：算法插件加载报 `ERROR_BAD_EXE_FORMAT (0xC1)`**
- 主程序 32 位、插件 64 位（或反之）。全部用 64 位工具链

**Q：改了 .pro 后增量编译行为怪异**
- 换编译器/清 .o 后必须重跑 qmake，Makefile 里烤的还是旧编译器路径

## 协议类

**Q：下位机发的帧上位机完全不认**
- 按顺序核对：帧头 `A5 5A` → LEN 是 payload 长度（大端）→ RSV 填 0 → CRC 覆盖**帧头+payload**、小端。对照[通信协议](通信协议.md)页的示例字节流
- 用「帧解码器」窗口看原始字节流逐字节对照

## 其他

**Q：截图/录像找不到文件**
- 都在 exe 同级：`images/`、`videos/`（Linux 在 `bin_linux/` 下）

**Q：启动 3 秒后弹检查更新失败**
- 私有仓库/无网络时正常，静默失败不影响使用
